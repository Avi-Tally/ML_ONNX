### 1. Bill-Wise Opening Balance Extraction & Calculation
- **Summary**: Updated `fetch_ledgers()` in `tally_client.py` to accept a `balance_type` parameter ("opening" vs "closing"). When `balance_type="opening"`, the client fetches both base ledger `OpeningBalance` tags and secondary `BillOpeningList` collection XML payloads to aggregate bill-wise allocations.
- **Touched Files**: `tally_client.py`
- **Key Implementation Snippet**:
  ```python
  # tally_client.py: fetch_ledgers with bill-wise opening balance support
  def fetch_ledgers(self, company_name, port, balance_type="closing"):
      tag_name = "OPENINGBALANCE" if balance_type == "opening" else "CLOSINGBALANCE"
      payload_ledgers = f"""<ENVELOPE>
  ...
          <COLLECTION NAME="LedgerListWithBalance">
              <TYPE>Ledger</TYPE>
              <FETCH>Name, ClosingBalance, OpeningBalance</FETCH>
          </COLLECTION>
  ..."""
      # Fetch BillOpeningList when opening balance is requested
      if balance_type == "opening":
          payload_bills = f"""<ENVELOPE>...<COLLECTION NAME="BillOpeningList"><TYPE>Bill</TYPE><FETCH>Parent, OpeningBalance</FETCH></COLLECTION>...</ENVELOPE>"""
          res_bills = self.execute_xml_request(port, payload_bills)
          root_bills = ET.fromstring(res_bills)
          bill_ops = {}
          for b_elem in root_bills.findall(".//BILL"):
              parent = (b_elem.findtext("PARENT") or b_elem.attrib.get("PARENT", "")).strip()
              if parent:
                  op_str = b_elem.findtext("OPENINGBALANCE") or "0.00"
                  try:
                      bill_ops[parent] = bill_ops.get(parent, 0.0) + float(op_str)
                  except ValueError:
                      pass
          for name_key in list(ledgers.keys()):
              if name_key in bill_ops:
                  try:
                      base_val = float(ledgers[name_key])
                      ledgers[name_key] = f"{(base_val + bill_ops[name_key]):.2f}"
                  except ValueError:
                      pass
      return ledgers
  ```

## Technical Decisions & Trade-offs
- **Bill-Wise Allocation Addition**: Opening balance in Tally for bill-by-bill ledgers is split between ledger master `OpeningBalance` and `BillOpeningList` entries. Combining both ensures 100% mathematical parity with Tally UI (e.g. K. L. Stores opening balance ₹ 30,800.00 Dr).
- **Process Discovery vs Port Scanning**: Pure port scanning across 9000-9010 took ~730ms. PowerShell process lookup directly identifies active Tally PIDs and their exact listening ports (`netstat -ano`), isolating custom ports like `12345` or `10089` seamlessly.
- **Sequential ONNX Model Execution Analysis**: Analyzed why the 11 ONNX classifier sessions take ~1.5–2.0s during `parse_query()`. The root cause is single-threaded sequential execution of 11 distinct `.run()` calls plus string tensor object conversion in `onnxruntime`.
