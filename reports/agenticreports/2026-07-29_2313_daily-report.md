## Accomplishments & Features Built

### 1. Tally Context Caching
- **Summary**: Implemented process-level caching for `update_routing_table` to prevent the NLP engine from forcing Tally to serialize its entire Chart of Accounts into XML on every single query.
- **Touched Files**: `tally_client.py`, `mcp_server.py`
- **Key Implementation Snippet**:
  ```python
  # In tally_client.py (update_routing_table)
  # CACHING: Prevent hammering Tally during rapid batch tests
  if self.routing_table:
      return self.routing_table
  ```
  ```python
  # In mcp_server.py (_query_tally_internal)
  # Retrieve cached context from the routing table instead of hitting Tally again
  ctx = {}
  for k, v in tally_client.routing_table.items():
      if v["port"] == port and v["name"].lower() == company_name.lower():
          ctx = v.get("context", {})
          break
  ```
- **Rationale / Design Notes**: Without this cache, 100 consecutive queries caused 100 massive (~5MB) XML exports back-to-back, which rapidly exhausted Tally's internal XML serialization buffers and led to a fatal crash.

### 2. TCP Socket Hardening (Timeout & Cleanup)
- **Summary**: Raised HTTP timeouts to 90 seconds to accommodate massive global outstandings queries (which take Tally up to 104 seconds to compute). Added robust socket closure in `finally` blocks to prevent TCP RST (broken pipes) from crashing Tally during abrupt client termination.
- **Touched Files**: `tally_client.py`
- **Key Implementation Snippet**:
  ```python
  # In tally_client.py (execute_xml_stream)
  response = requests.post(url, data=payload, headers={'Content-Type': 'text/xml'}, timeout=(5.0, 90.0), stream=True)
  ...
  finally:
      if 'response' in locals() and hasattr(response, 'close'):
          response.close()
  ```
- **Rationale / Design Notes**: Tally was crashing when the python HTTP client `requests` timed out at 25 seconds and dropped the connection while Tally was still generating the response. Extending the read timeout ensures Tally finishes writing to the socket cleanly.

## Technical Decisions & Trade-offs
- **[Decision 1]**: Extending HTTP timeouts to 90.0 seconds.
