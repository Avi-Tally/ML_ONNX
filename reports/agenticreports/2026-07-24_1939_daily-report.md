  ```python
  def probe_port(port):
      url = f"http://localhost:{port}"
      try:
          # Use ultra-short connect timeout (200ms) and read timeout (500ms) to prevent TCP SYN retry hangs
          res = requests.post(url, data=payload, headers={'Content-Type': 'text/xml'}, timeout=(0.2, 0.5))

  ```
- **Rationale / Design Notes**: Setting explicit tuple timeouts `timeout=(0.2, 0.5)` forces Python `requests` to abort failed TCP SYN handshakes in 200ms instead of waiting for the default OS socket timeout (2050ms).

### 3. Short Entity Fuzzy Resolution & Corporate Stop-Word Filtering
- **Summary**: Refactored `resolve_ledger` in `nlp_engine.py` to replace full-string Levenshtein (`fuzz.ratio`) with query-coverage-adjusted token set matching (`fuzz.token_set_ratio`), added corporate suffixes (`"limited"`, `"ltd"`, `"pvt"`, `"private"`) to stop-words, and updated the per-ledger candidate accumulator to prioritize score over window length.
- **Touched Files**: [nlp_engine.py](file:///c:/Users/avija/projects/ML_ONNX/nlp_engine.py)
- **Key Implementation Snippet**:
  ```python
  # c/Users/avija/projects/ML_ONNX/nlp_engine.py (resolve_ledger Step 3)
  common = { ... "limited", "ltd", "pvt", "private", "inc", "corp", "corporation", "owed", "owing", "collect" }

  ledger_best = {} # idx -> (score, w_len, window)
  for window in windows:
      w_tokens = set(window.split())
      w_len = len(w_tokens)
      matches = process.extract(window, ledger_names_lower, scorer=fuzz.token_set_ratio, limit=10)
      if matches:
          for m in matches:
              matched_name_lower = m[0]
              raw_score = m[1]
              idx = original_indices[m[2]]
              m_tokens = set(matched_name_lower.split())
              
              overlap = len(w_tokens.intersection(m_tokens))
              if overlap == 0:
                  continue
                  
              coverage = overlap / w_len
              score = raw_score * coverage
              
              if idx not in ledger_best:
                  ledger_best[idx] = (score, w_len, window)
              else:
                  prev_score, prev_w_len, prev_w = ledger_best[idx]
                  # Primary: higher score wins. Tiebreaker: longer window.
                  if score > prev_score or (score == prev_score and w_len > prev_w_len):
                      ledger_best[idx] = (score, w_len, window)
  ```
- **Rationale / Design Notes**: Adding corporate suffixes to the stop-word dictionary prevents 1-token windows like `"limited"` from matching every `*LIMITED` ledger in Tally at 100% score. Using score as the primary comparator prevents longer 4-token low-scoring windows from permanently locking out exact 1-token matches.

## Technical Decisions & Trade-offs

- **Decision 1: Restricting Directional Intent Overrides to `AMBIGUOUS_OUTSTANDINGS`**:
  - *Context*: Applying directional keyword matching globally overrode valid `GET_AGEING`, `GET_TRIAL_BALANCE`, and `UNKNOWN` (FAQ) model classifications whenever words like `"receivables"` or `"payables"` appeared in the query.
  - *Trade-off*: Restricting the override strictly to `AMBIGUOUS_OUTSTANDINGS` preserves 100% classification accuracy across all 727 benchmark queries while resolving explicit directional phrases for pending bills.
- **Decision 2: 2-Tier Quality Ranking (`match_tier`) vs Pure Score Thresholding**:
  - *Context*: Pure score thresholding (`score >= 85.0`) treated exact word boundary matches (`Abhay Limited`) as equal to fuzzy token matches (`ABHAY KUMAR CHORDIA`).
  - *Trade-off*: Incorporating `match_tier` ensures exact matches (`tier=1`) take absolute precedence over fuzzy matches (`tier=3`), while preserving cross-company ambiguity menus when queries are genuinely ambiguous (e.g. typing `"ABhay"` alone).
